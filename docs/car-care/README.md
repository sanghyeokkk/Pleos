# 내 차 관리 프로토타입

차량용 정비 기록 앱입니다. 사용자 입력 이력을 기기에 저장하고 마지막 정비일·주행거리와 사용자가 설정한 주기에서 다음 점검 시점을 계산합니다. 소모품 마모를 진단하거나 제조사가 제시한 실제 교체 시기를 자동 판정하지 않습니다.

## 현재 동작

- 정비 항목, 날짜, 당시 주행거리, 거리·기간 주기, 선택적 비용을 입력하고 저장·수정·삭제합니다. 항목별 최신 이력으로 점검 시기를 계산합니다.
- 정비 기록의 빠른 선택에 `타이어 위치 교환`을 제공합니다. 기존 `타이어` 기록과 별도로 교환일과 당시 주행거리를 기록하며, 점검 주기는 사용자가 확인해 입력합니다.
- Vehicle SDK `getCurrentDistanceDriven`을 사용하여 앱이 보이는 동안 시작 시와 이후 약 60초마다 현재 누적거리를 읽습니다. 조회 실패·미지원 시에만 직접 입력 버튼을 제공합니다. 직접 입력값은 임시로 화면 계산에 사용하고 백그라운드 알림에는 사용하지 않습니다. 차량 값 조회에 성공하면 차량 값을 우선하고 임시 입력은 지워집니다. 실차에서 값·단위와 갱신은 확인이 필요합니다.
- 이전 정비 당시 거리보다 현재 거리가 작은 경우 거리 기준 결과를 계산하지 않고 입력 확인을 안내합니다.
- 기어가 P이며 AAOS `CarUxRestrictions`에서 주의 분산 최적화 및 입력·설정·필터 제한이 없는 경우에만 기록 편집과 정비소 검색을 허용합니다. 상태가 확인되지 않으면 잠급니다. 2026-11-05 에뮬레이터에서 기어를 D로 변경하자 제한 상태가 바뀌고 기록 편집·정비소 검색이 비활성화됐으며, P로 복원한 뒤 다시 활성화됐습니다. 기어와 제한 값이 동시에 바뀐 시험으로 각각의 독립 동작이나 실차·지역별 정책의 준수까지 검증한 것은 아닙니다.
- `주변 정비소` → `내비게이션에서 블루핸즈 찾기`는 NaviHelper의 `requestNavigationScreen(SearchPlace("블루핸즈"))`를 호출합니다. Pleos 내비게이션이 검색 결과를 표시하며, 사용자가 그 화면에서 지점을 선택하고 목적지로 설정합니다. 결과 목록을 차계부 화면으로 가져오는 방식이 아닙니다. `NAVI_CUSTOM_MAP` 권한과 내비게이션 연결이 필요합니다.
- 정비소 검색은 사용자 요청 시 위치 권한을 받은 뒤 현재 위치를 `overpass-api.de`로 전송해 OpenStreetMap 정비소 후보를 조회합니다. 데이터는 © OpenStreetMap contributors이며, 영업 상태나 특정 정비 취급 여부는 보장하지 않습니다. 공개 Overpass 서버는 시제품 시험용이며 상용화 전에 공급자 정책·가용성·라이선스를 검토해야 합니다.
- 정비소를 선택하면 좌표로 NaviHelper 경로 요청을 시도합니다. 외부 장소의 POI 식별자 호환성 및 실제 성공 응답은 아직 검증되지 않았습니다.
- 사용자가 주차 중 `정비 점검 알림`을 켜고 필요 시 알림 권한을 허용하면 최신 기록을 약 하루마다 확인합니다. 백그라운드에서 차량 주행거리를 읽은 경우 거리와 날짜를 함께 확인하고, 조회 실패·미지원 시 날짜 기준만 확인합니다. 테스트용 직접 입력 거리는 알림에 사용하지 않습니다. 안드로이드 작업 스케줄에 따라 지연될 수 있으며 기기 정책, 알림 설정 또는 앱 강제 중지에 영향을 받습니다. 알림을 끄면 예약을 취소합니다.

## Gleo 연동 초안

`assets/schema.json`에 정비 기록 초안(`ADD_MAINTENANCE_RECORD`), 항목별 최신 이력(`GET_MAINTENANCE_RECORD`), 점검 현황(`GET_MAINTENANCE_DUE`)을 정의했습니다. 입력한 항목과 선택적 날짜·비용을 검토 화면에 넣으며, 사용자가 화면에서 저장하기 전에는 기록하지 않습니다. 조회는 저장된 이력과 조회 당시 차량 거리를 사용하며 서로 다른 단위인 거리와 날짜 중 무엇이 먼저 도래할지 추정하지 않습니다. 음성으로 저장을 승인하는 동작은 구현하지 않았습니다.

공식 문서의 Intent 전달 형식에는 JSON `ACTION_PARAM`과 개별 extra 설명이 모두 있어 두 형태를 수용합니다. 모의 Android Intent로 항목·날짜·비용 초안과 점검 조회 결과가 만들어지는 것을 확인했습니다. 에뮬레이터의 `ai.umos.ambientai`로만 응답을 전송하며, Gleo가 대기 중인 모의 시험에서 응답은 수신 후 거부됐습니다. 실제 발화·응답, 스키마 등록·승인, 호출자 검증과 다른 차량 버전에서의 수신 패키지는 별도로 검증해야 합니다. 일반 Android Intent 시험은 실제 Gleo 음성 연동의 성공을 의미하지 않습니다.

2026-11-05에는 존재하지 않는 항목 조회가 기록 없음으로, 항목이 빠진 기록 요청과 미래 날짜 요청이 추가 입력 요청으로 응답하는 것을 모의 Intent로 확인했습니다. Gleo 프로세스가 응답을 수신했으나 음성 세션이 대기 상태여서 거부했습니다. 에뮬레이터의 `hw.audioInput=no`로 실제 마이크 음성 호출은 진행하지 못했습니다.

## 실험 및 제한

- `Pleos_Connect_v2.1.0` 에뮬레이터(이전 이름 `Pleos_Speech_Recovery`)에서 주행거리 응답 `0 km`를 확인했습니다. 실차에서 조회값과 단위를 확인해야 합니다.
- 2026-11-03 에뮬레이터에서 공개 시험 좌표로 기본 Overpass 서버 요청을 재시험했으나 HTTP 502가 반환됐습니다. 별도로 시험한 대체 서버도 HTTP 429를 반환했으므로 실제 정비소 검색과 길 안내 성공은 미확인입니다. 결과 파싱은 고정 데이터 테스트로 확인했습니다.
- 같은 에뮬레이터에서 Pleos 내비게이션의 블루핸즈 검색 결과 목록을 확인하고 삼평점을 선택해 실제 경로 안내가 시작되는 것을 확인한 뒤 시험 안내를 종료했습니다. 이는 Pleos 내비게이션 화면에서 이루어진 시험이며, Overpass 결과를 `requestRoute()`에 전달하는 기존 일반 정비소 경로는 검증된 것이 아닙니다. 실차·다른 지역의 결과와 사용 가능 여부는 추가 확인해야 합니다.
- 2026-11-05 내비게이션 지도 배경이 비어 있는 문제가 확인됐습니다. 기존 AVD의 하드웨어 렌더링과 새 별도 AVD의 SwiftShader에서 모두 재현됐으나, AVD 데이터와 초기화 상태가 달라 원인이 GPU가 아니라고 단정할 수는 없습니다. 별도 새 AVD의 GPS NMEA 검증 오류도 재현됐습니다. Android 에뮬레이터의 구버전 [GPS 구현](https://android.googlesource.com/platform/external/qemu/+/refs/heads/studio-1.4-dev/android/gps.c)에는 고정된 임시 체크섬을 사용하는 코드가 있으나 현재 설치 버전과 동일하다고 확정한 것은 아닙니다. 테스트용 AVD는 종료·삭제했으며 기존 AVD는 유지했습니다.
- 추가 확인: 실행 중인 Android Emulator 37.2.12.0의 `qemu-system-x86_64.exe`에서 GPGGA/GPRMC 형식 문자열과 고정 `*47` 문자열을 확인했습니다. 내비게이션 로그의 두 문장은 이 생성 형식과 일치하며 내용이 바뀌어도 `*47`을 사용합니다. 따라서 에뮬레이터의 GPS 문장 생성이 유력한 원인이지만, 실행 경로를 직접 추적하지는 못했습니다. Android 위치 서비스는 동일 시점에 좌표를 정상 수신하고 있었습니다. 같은 좌표의 올바른 체크섬 문장을 `geo nmea`로 한 번 전송했을 때 명령은 성공했으나, 내비게이션의 수신·처리는 확인되지 않았고 기존 오류는 계속됐습니다. 지도 배경 문제와의 인과관계도 미확인입니다.
- 지도 추가 확인: 사용자가 바다·해안선은 보이지만 확대해도 도로가 보이지 않는 화면을 확인했습니다. 내비게이션 `3.3.2-rc5-hotfix.3`의 로그에서 일부 지도 아이콘 누락 경고와 장소 상세 조회의 `code: 500, msg: Not Found`를 확인했습니다. 이 장소 조회 실패와 도로 지도 표시 사이의 연관은 확인되지 않았습니다. Android 네트워크는 연결·검증 상태이나 지도 데이터 서버의 정상 응답을 증명하지는 않습니다. 상세 지도 오류의 원인과 해결책은 미확정입니다.
- 내비게이션 프로세스만 다시 시작한 후에도 도로는 표시되지 않았습니다. 재시작 직후 Android 위치 서비스의 좌표와 화면의 `수정구 시흥동` 표기가 서로 달랐고 NMEA 체크섬 오류는 계속됐습니다. 화면이 해당 좌표로 실제 이동했는지, GPS 오류가 지도 표시를 막는지는 확인되지 않았습니다. 재시작 중 충전 사업자 조회의 인증 오류도 기록됐으나 지도 데이터 요청 오류로 확인된 것은 아닙니다. 정비 기록과 기기 데이터를 지우지 않았습니다.
- 2026-11-05 격리된 시험 저장소에서 정비 기록 작성·수정·삭제, 차량 거리 입력, 거리 기준 계산, 점검 시기 도달과 블루핸즈 검색 요청 버튼을 확인했습니다. 실제 앱의 해당 버튼으로 Pleos 내비게이션의 블루핸즈 목록이 열렸고, 사용자가 지점과 목적지를 선택한 뒤 삼평점 안내 시작 화면이 표시되는 것을 확인했습니다. 자동 시험 도구가 내비게이션 분할 화면을 조작하지 못해 사용자가 마지막 선택을 수행했습니다. 사용자의 정비 기록은 시험 저장소에 사용하지 않았습니다.
- 에뮬레이터에서 예약 작업을 강제 실행해 날짜 기준 알림을 확인했습니다. 2026-11-05에는 엔진오일 기록(교체 당시 62 km, 10,000 km 주기)을 이용해 차량 값 10,061 km에서 1 km 남음, 10,062 km에서 점검 시기 도달 및 강제 실행 알림을 확인했습니다. 정기 실행 시각과 재부팅·실차 동작은 추가 시험이 필요합니다. 스마트폰 알림은 제공하지 않습니다.
- 차량별 정비 주기 자동 제공, 리콜 판별, 예약, OCR, 가족 간 동기화는 제공하지 않습니다.
